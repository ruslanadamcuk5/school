# 📚 Учусь · 3–4 класс

Мультиарендная образовательная платформа для **3–4 класса** по программе
**Республики Беларусь**: математика, русский и белорусский язык и литература,
английский язык, «Человек и мир». Игровой тренажёр по математике с разными способами
объяснения, кабинеты учителя, ученика, родителя и администратора, проверочные
и контрольные работы, расписание и библиотека учебных пособий в PDF.

Приложение полностью автономно: без внешних CDN, без ключей API, без интернета —
озвучка (Web Speech API) и звуки (Web Audio API) работают в браузере.

Дополнительно в проекте есть:

* **REST API** `/api/v1` для мобильных клиентов (см. [docs/API.md](docs/API.md));
* **Android-приложение** на Kotlin + Jetpack Compose с кабинетами всех ролей,
  сборка APK через GitHub Actions (см. [android/](android/));
* **готовый деплой** на бесплатный Alwaysdata (см.
  [deploy/alwaysdata/README.md](deploy/alwaysdata/README.md)).

## 🚀 Быстрый старт

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate

pip install -r requirements.txt

python seed.py            # создать/обновить базу, наполнить программой
python run.py             # http://127.0.0.1:5000
```

При первом запуске в консоль выводятся два секрета — **сохраните их**:

* `PIN-код родительской зоны` — вход в семейный режим без аккаунта;
* `логин admin, пароль …` — учётная запись администратора (по умолчанию `math2025`,
  смените пароль в профиле).

Задать свои значения: `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `ADMIN_EMAIL`, `SECRET_KEY`.

В режиме разработки сервер **сам перезагружается** при изменении кода и **откажется
запускаться**, если порт уже занят другим экземпляром: в Windows несколько процессов
могут «поделить» порт, и тогда запросы попадают на устаревшую версию кода
(`BuildError: Could not build url for endpoint …`). Если такое случилось — закройте
старый процесс и запустите сервер заново:

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*run.py*' -or $_.CommandLine -like '*edu-math*app.py*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

## 👥 Роли и режимы

| Роль | Что доступно |
|---|---|
| **Администратор** | Сводка по платформе, пользователи, города → школы → классы, предметы и курсы, загрузка PDF-пособий, журнал действий |
| **Учитель** | Свои классы и ученики, настройка тем в курсе, проверочные/контрольные работы с выбором тем, расписание, пособия класса |
| **Ученик** | Кабинет с учителем и классом, назначенные работы, расписание, учебники, значки, тренировка по темам |
| **Родитель** | Статистика и работы своего ребёнка (привязка по коду ребёнка) |
| **Семейный режим** | Прежний режим без регистрации: выбрать профиля ребёнка и заниматься |

### Регистрация
`/register` — выбор роли, логин, пароль и организация:

* **Ученик** — город → школа → класс; **учитель класса подтягивается автоматически**.
  Каждому ученику выдаётся 6-символьный код, по которому родитель привязывает ребёнка.
* **Учитель** — город → школа → отмечает классы, которые ведёт (они закрепляются за ним).
* **Родитель** — код ребёнка (можно привязать позже в профиле).

Роль администратора через регистрацию **не выдаётся** — только через `seed.py`/переменные окружения.

### Вход и регистрация через Google

Если заданы `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`, на страницах входа и
регистрации появляется кнопка **«Войти через Google»**. Без этих переменных
кнопка скрыта, а маршруты `/auth/google*` отвечают 404 — обновление безопасно
выкладывать до настройки.

Как это работает:

* новый пользователь после Google выбирает роль (ученик/учитель/родитель),
  имя и логин; почта берётся из Google и не редактируется;
* если аккаунт с такой почтой уже есть и Google к нему не привязан, он
  привязывается автоматически (Google подтвердил владение почтой);
* пароль не обязателен: аккаунт живёт на входе через Google, пароль можно
  задать позже в профиле;
* в профиле есть «Привязать Google» / «Отвязать Google»; отвязка требует
  заданного пароля, чтобы не потерять доступ;
* `state` одноразовый и хранится в сессии, почта принимается только с
  `email_verified=true`, один Google-аккаунт (`sub`) — только у одной учётной
  записи.

Настройка в Google Cloud Console:

1. [console.cloud.google.com](https://console.cloud.google.com/) → создайте
   проект → **APIs & Services → OAuth consent screen** (тип External; для
   тестирования добавьте себя в Test users).
2. **Credentials → Create credentials → OAuth client ID → Web application**.
3. В **Authorized redirect URIs** добавьте:
   * `https://virusadk.alwaysdata.net/auth/google/callback` — продакшн;
   * `http://127.0.0.1:5000/auth/google/callback` — локальная разработка.
4. Скопируйте Client ID и Client secret в `.env`:

```bash
GOOGLE_CLIENT_ID=…apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=…
# Необязательно: точный адрес callback, если сайт за прокси
GOOGLE_REDIRECT_URI=https://virusadk.alwaysdata.net/auth/google/callback
```

Можно не задавать переменные в панели хостинга, а положить те же данные в
файл `data/google_oauth.json` (каталог `data/` не попадает в git и в архив
выкладки):

```json
{"client_id": "…apps.googleusercontent.com", "client_secret": "…"}
```

Кнопка появляется сразу после сохранения файла — перезапуск не нужен.

В Android-приложении на экране входа есть кнопка **«Войти через Google»**.
Она работает через Credential Manager и тот же Web Client ID: приложение
получает Google ID token и отправляет его на сервер
(`POST /api/v1/auth/google`). Новый пользователь выбирает роль, имя и логин
прямо в приложении, пароль не нужен. Если на устройстве нет подходящего
аккаунта или Credential Manager не сработал, приложение предлагает
**«Войти через Google в браузере»**: открывается страница сайта, после входа
браузер возвращается в приложение по ссылке `uchus://auth` (одноразовый код
меняется на токен через `POST /api/v1/auth/google/exchange`). Новый
пользователь в этом случае выбирает роль на странице сайта.

Для нативного входа в том же проекте Google Cloud нужен **Android OAuth-клиент**
(`Credentials → Create credentials → OAuth client ID → Android`):

* package name: `com.edumath.uchus`;
* SHA-1 debug-ключа из `android/keystore/uchus-debug.keystore`:
  `F5:06:F6:8C:08:C4:31:DC:3F:70:49:CF:5C:88:8A:26:78:FA:70:96`.

Без него Credential Manager не может подтвердить, что запрос делает именно
это приложение, и Google отвечает `DEVELOPER_ERROR` или
`[16] Account reauth failed` (в приложении это выглядит как «вход отменён»).
Если APK будет подписан release-ключом или ключом Google Play, добавьте и его
SHA-1 отдельным Android-клиентом. Web Client ID при этом не меняется: он
по-прежнему передаётся в `serverClientId`.

Также проверьте, что OAuth consent screen имеет тип **External** (для обычных
Gmail), а в статусе Testing почта пользователя добавлена в **Test users**.

Web Client ID зашит в сборку по умолчанию. Другой проект Google можно указать
при сборке APK:

```bash
cd android
gradle assembleDebug -PgoogleClientId=…apps.googleusercontent.com
```

## 🎓 Кабинет учителя

* **Классы и ученики** — список своих классов, точность и XP каждого ученика, добавление ученика по логину.
* **Курсы** — курс = предмет + класс + набор тем. Учитель включает/выключает темы и задаёт порядок.
* **Работы** — проверочные, контрольные, срезы, тренировочные: выбор тем **любого
  предмета**, число заданий, ограничение по времени, срок сдачи, статус
  (черновик → опубликована → закрыта). По математике генерируются вычислительные
  задания, по остальным предметам — вопросы по тексту пособия: пропущенное слово,
  страница, предмет и описание темы. Задания **фиксируются** при создании, поэтому все
  ученики получают одинаковые вопросы, а проверка идёт по сохранённым ответам.
  Результаты — балл, процент, оценка по 10-балльной шкале, время выполнения.
* **Расписание** — недельная сетка уроков: день, номер, предмет, тема, время.
* **Пособия** — все загруженные PDF по предметам и классам.
* **Библиотека** (`/library/`) — загрузка книг, доступ классами, рекомендации тем
  ученикам (см. «Библиотека и чтение»).

## 🎒 Кабинет ученика

Мой класс и учитель, назначенные работы с разбором, расписание, учебники с переходом
на нужную страницу PDF, значки, привычная тренировка по карте тем и **своя библиотека**

## 🛍 Магазин приключений

Магазин (`/shop/`, в Android — пункт «Магазин») рассчитан на детей 1–4 классов.
Покупать можно за **монеты и свободный опыт**, а уровень считается по всему
заработанному опыту (`xp + xp_spent`) — покупка **не понижает** ребёнка в уровне.

| Категория | Что внутри | Зачем ребёнку |
|---|---|---|
| 🎓 Учёба | двойной опыт, двойные монеты (30 мин), мешок +3 подсказки, умные подсказки (+1 навсегда), щит серии | реально помогает решать и не терять огонёк |
| 🎨 Стиль | 4 набора аватаров, 3 рамки, 3 титула, 2 темы сайта | видно друзьям, меняет профиль и оформление |
| 🐾 Питомцы | кот, сова, дракончик | растут за верные ответы: Малыш → Друг → Помощник → Защитник → Легенда |
| 🧱 Minecraft | кирка (+15 % монет навсегда), зачарование (+15 % опыта навсегда), зелье +5 подсказок, ТНТ-лутбокс, набор мобов, алмазная рамка, тема «Кубический мир», крипер-питомец | любимые механики и предметы, которые хочется собрать |

* **Подарки от администратора** — конкретному ребёнку с причиной «за что»:
  за серию, точность, рост активности. Ребёнок сам открывает подарок в магазине
  (на сайте и в Android), видит причину и личное сообщение.
* **Админка магазина** (`/admin/shop` на сайте и вкладка «Магазин» в Android) —
  рейтинг стараний за 7 дней с подсказками «кто заслуживает подарок», идеи
  подарков (чего у ребёнка ещё нет), правка цен и скидок, включение/выключение
  товаров, товар дня, объявление и живые события.
* **Живые события** — двойные монеты, двойной опыт или скидка на весь магазин
  с датами начала и окончания; дети видят баннер и получают бонус.
* **Товар дня** — скидка 25 % на один товар: выбор админа на сегодня или
  автоматически по дате.
* **Сундук дня** — бесплатно 10–20 монет и 2–6 опыта, раз в сутки.
* **Редкости** — обычный / редкий / эпический / легендарный выводятся из цены и
  уровня и подсвечиваются на карточках.
* Усилители складываются: повторная покупка продлевает время.
* Подсказки из мешка расходуются в заданиях, щит автоматически спасает серию
  за один пропущенный день.
* Каталог живёт в коде (`services/shop.py`), админские правки — в
  `shop_item_overrides` (пустое поле = значение из кода), в базе также покупки,
  количество расходуемых предметов, прогресс питомцев, подарки и события.
* API для Android: `GET /api/v1/shop`, `POST /api/v1/shop/{buy,equip,avatar,chest}`,
  `POST /api/v1/shop/gifts/claim`; админка — `GET /api/v1/admin/shop`,
  `POST /api/v1/admin/shop/{items,gifts,events}/…`.

## 📚 Библиотека и чтение

Глобального (онлайн) каталога в приложении нет: **библиотека принадлежит школе,
а наполняет её учитель**. Общий адрес — `/library/`.

**Учитель** (`/library/`):

* **Загружает книгу** (PDF) с предметом и классом. Книга сразу **разбивается на темы
  по оглавлению** — тот же разбор закладок и страницы «Содержание», что и для пособий.
* **Отмечает классы**, которым книга доступна: их ученики видят книгу в своей библиотеке.
* Открывает страницу книги: список тем со страницами, ручное добавление тем
  («Название — страница»), повторный импорт оглавления, удаление лишних тем.
* **Рекомендует тему** (или книгу целиком) классам и/или отдельным ученикам
  с комментарием. Отправленные рекомендации и прогресс чтения — в разделе
  «Мои рекомендации» (`/library/recommendations`), там же можно отозвать рекомендацию.

**Ученик** (`/library/`) видит книги, открытые его классам, и рекомендации учителя;
открывает тему на нужной странице PDF одним кликом (`#page=N`) и отмечает «прочитано» ✅.

**Родитель** видит библиотеку своего ребёнка в режиме чтения (без отметок).

PDF книги отдаётся только тем, кому она доступна (`/library/open/<textbook_id>`),
файлы хранятся в `data/uploads/`.

## 🎨 Темы оформления

Оформление выбирается автоматически по роли и классу (`body.theme-*`):

| Кто | Тема | Что видно |
|-----|------|-----------|
| Ученики 1–4 классов | `playful` | Игровая: звёзды, монеты, комбо, анимации, пестрые карточки |
| Ученики 5–7 классов | `strict` | Строгая, без игровых элементов: приглушённая гамма, спокойные карточки |
| Ученики 8–11 классов, учителя, администратор, родители | `adult` | Взрослая: тёмно-синий/серый, плоские карточки, минимум анимации |

## 📖 Учебные пособия (PDF) и темы предметов

Администратор (раздел `/admin/textbooks`) или **учитель** (раздел `/library/`) загружает
PDF (до 60 МБ, лимит — `MAX_UPLOAD_MB`) с указанием **предмета и класса**. При включённой
галочке приложение офлайн разбирает **закладки PDF или страницу
«Содержание»** — в начале **или в конце** книги, склеивает названия тем, перенесённые
на две строки, создаёт темы предмета и привязывает каждую к диапазону страниц. Если
текстовый слой повреждён, подключается `PyMuPDF` и восстанавливается кодировка
CP437→CP1251; для оглавлений с отдельным столбцом номеров страницы сопоставляются
по порядку. Повторный импорт обновляет страницы и убирает старые PDF-артефакты
(обложка, имя файла, пустая страница), не трогая темы с прогрессом.

Если PDF — скан без текстового слоя, темы добавляются вручную:

* на странице пособия — список «Название — страница»;
* в админ-панели: **Предметы → Темы** — создание, переименование, порядок, удаление;
* в курсе учителя — кнопка «Добавить тему» и выбор тем для класса.

Темы математики остаются тренировочными: для них работают генераторы заданий и 63 способа
объяснения. Темы остальных предметов — режим чтения: карточка темы, все пособия с нужными
страницами, встроенный просмотр PDF, тест по теме и отметка «изучено» (+XP, ⭐ один раз).
Тест собирается офлайн из текста указанных страниц: пропущенное слово, страница,
предмет и описание темы. Если PDF — скан без текста, остаются вопросы по теме и пособию.

Ученик и учитель видят пособия своего класса и открывают нужное место одним кликом
(`#page=N&zoom=page-width`). Загруженные файлы хранятся в `data/uploads/` (каталог
настраивается `UPLOAD_DIR`).

## 🤖 Искусственный интеллект (необязательно)

ИИ — **необязательная надстройка**. По умолчанию он **выключен**, приложение работает
полностью офлайн и не делает внешних запросов. Пока модель не подключена, кнопки и
страницы ИИ не отображаются, а маршруты `/ai/...` отвечают 404 — всё работает как раньше.

Администратор подключает облачную модель в разделе **`/admin/ai`**:

* выбор провайдера (по умолчанию **OpenRouter**), адрес API, модель, ключ доступа,
  `temperature`, лимит токенов и общая подсказка для модели;
* кнопка **«Проверить связь»** отправляет короткий тестовый запрос и показывает ответ
  или ошибку;
* статистика обращений и последние ошибки; очистка готовых объяснений.

Все провайдеры работают по OpenAI-совместимому протоколу
(`POST <адрес>/chat/completions`), поэтому поддерживаются OpenRouter, OpenAI, Groq,
Mistral, DeepSeek, Google Gemini (OpenAI-совместимый режим), локальный Ollama и любая
другая совместимая служба. Запросы идут **только с сервера** — браузер не обращается
к внешним сервисам, CSP приложения не меняется.

Возможности для ученика и учителя (когда ИИ включён):

* **Объяснение темы** — кнопка «🤖 Объяснить с ИИ» на странице каждой темы
  (`/ai/explain/<тема>`): модель объясняет тему иначе, чем учебник, — простыми словами,
  с правилом, разбором примеров по шагам, частыми ошибками, советами по запоминанию и
  тремя вопросами для самопроверки. Готовые объяснения **кэшируются** в `ai_explanations`
  и открываются мгновенно; кнопка «🔄 Обновить объяснение» генерирует заново.
  Объяснение можно **прослушать**: в браузере — кнопка «🔊 Прослушать» (Web Speech API),
  в Android-приложении — кнопка «Озвучить» и автоматическое чтение системным
  синтезатором речи (без внешних сервисов).
* **Тесты по темам учебников** — вопросы к тесту по выбранной теме составляет ИИ
  (`services/ai_quiz.py`): 8 вопросов с вариантами ответов, проверкой правильного
  варианта и пояснением. Вопросы кэшируются в `ai_quizzes`, поэтому повторный тест
  открывается мгновенно. Вопросов «на какой странице» и «к какому предмету» больше нет;
  если ИИ выключен, используется офлайн-запасной вариант по описанию темы.
* **Помощник по приложению** — постоянная кнопка «🤖 Помощник» внизу справа
  (`/ai/assistant`) и отдельная страница: подсказывает, где найти тему, как пройти тест,
  как назначить работу, как подключить книгу. История диалога хранится в сессии.

Доступно и вошедшим пользователям, и семейным профилям без аккаунта; анонимным
посетителям и при выключенном ИИ — недоступно. Есть простое ограничение частоты
запросов на сессию (`AI_MAX_PER_HOUR`), журнал обращений (`ai_requests`) и безопасная
разметка ответа (HTML экранируется, поддерживаются заголовки, списки и **жирный**).

## ☁️ Бесплатный хостинг (Alwaysdata)

Текущий рабочий адрес: **<https://virusadk.alwaysdata.net>** (Python WSGI,
SQLite, HTTPS). Проверка: <https://virusadk.alwaysdata.net/healthz>.

Пошаговая инструкция — в [deploy/alwaysdata/README.md](deploy/alwaysdata/README.md).
Коротко:

1. Зарегистрируйтесь на Alwaysdata (бесплатный тариф: 1 ГБ SSD, 256 МБ RAM,
   адрес `https://<логин>.alwaysdata.net`, Python WSGI).
2. Соберите архив:

   ```powershell
   python tools/make_deploy_zip.py            # без данных
   python tools/make_deploy_zip.py --with-data  # с текущей БД и PDF
   ```

3. Загрузите `dist/edu-math-deploy.zip` в `~/edu-math`, создайте virtualenv,
   установите `requirements.txt`, заполните `deploy/alwaysdata/.env`.
4. В панели создайте сайт **Python WSGI** с WSGI-файлом
   `/home/<логин>/edu-math/deploy/alwaysdata/wsgi.py`.
5. Проверьте `https://<логин>.alwaysdata.net/healthz` и войдите как `admin`.

`wsgi.py` сам читает `.env`, создаёт постоянный `SECRET_KEY` (если не задан) и
применяет миграции БД. Переменная `TRUST_PROXY=1` включает `ProxyFix`, чтобы
приложение видело HTTPS за прокси Alwaysdata.

Проверка окружения на сервере:

## 📱 Android-приложение

Каталог [android/](android/) — отдельный проект Kotlin + Jetpack Compose
(Material 3, Retrofit, OkHttp, Coil, DataStore). Работает с тем же сервером и той
же базой, что и сайт: изменения сразу видны в обоих интерфейсах.

### Возможности

| Кабинет | Что есть |
|---|---|
| **Ученик** | карта тем, магазин (усилители, стиль, питомцы), тренировки, тесты, ежедневное задание, работы, расписание, библиотека, чтение PDF-страниц, профиль, геолокация (по согласию), ИИ (если включён) |
| **Учитель** | сводка, классы и ученики, работы (создание, публикация, результаты), расписание, библиотека книг и рекомендации |
| **Родитель** | дети и их прогресс, привязка по коду, редактирование профиля, сброс прогресса, создание работ, библиотека ребёнка, карта детей и трек за день |
| **Администратор** | сводка, пользователи, города/школы/классы, темы, пособия, настройки ИИ, журнал, магазин (рейтинг, подарки, каталог, витрина и события) |

Загрузка новых PDF-пособий и разметка страниц выполняются на сайте (учитель или
администратор): мобильное приложение читает уже загруженные книги.

### Геолокация и карта

Родитель видит на карте, где находятся его дети, и может открыть трек за любой
день за последние 14 дней. Точки подписаны локальным временем (`ЧЧ:ММ`), рядом
показаны расстояние, длительность и время последней точки.

* **Согласие ребёнка.** Передача выключена по умолчанию. Ребёнок сам включает её
  на экране «Геолокация» (в приложении или на странице `/location`), там же может
  остановить передачу и удалить всю историю. Без согласия сервер отвечает
  `409 sharing_off` и точки не сохраняет.
* **Приватность.** История хранится 14 дней, доступна только привязанным
  родителям, самому ребёнку и администратору. Чужой профиль по прямой ссылке
  недоступен (404).
* **Android.** Передачу ведёт foreground service на `LocationManager` (без Google
  Play Services) с постоянным уведомлением. Точки отправляются пачками, дубликаты
  отсекаются по времени. Карта открывается в WebView с локальным Leaflet,
  тайлы — OpenStreetMap, внешний API-ключ не нужен. Разрешения
  `ACCESS_FINE_LOCATION` и `ACCESS_COARSE_LOCATION` запрашиваются только при
  включении передачи.
* **Веб.** `/parent/map` — карта с выбором ребёнка и даты, последними точками всех
  детей и кнопкой «Запросить геолокацию»; `/location` — страница ребёнка с
  браузерной геолокацией.
* **API.** Эндпоинты `/api/v1/location/*` и `/api/v1/parent/*/location` описаны в
  [docs/API.md](docs/API.md).

* **Семейный режим** — профили хранятся на устройстве (`X-Device-Id`), вход по PIN;
  доступны карта тем, тренировки, тесты, библиотека учебников своего класса и чтение.
* **Кэш чтения** — последние ответы API (карта, темы, библиотека, профиль,
  расписание) сохраняются на диск (JSON), поэтому при потере сети уже открытые
  экраны остаются доступными; полноценной офлайн-записи нет.
* **Адрес сервера** задаётся на экране входа и запоминается. Значение по умолчанию
  задаётся при сборке: `-PserverUrl=https://…`.
* **Вход через Google** — кнопка на экране входа (Credential Manager). Новый
  пользователь выбирает роль, имя и логин прямо в приложении, пароль не нужен.
* Все тексты интерфейса — на русском; внешних CDN и аналитики нет.

### Сборка APK через GitHub Actions

В проекте уже есть workflow
[.github/workflows/android.yml](.github/workflows/android.yml). Он собирает
**debug APK** (подписан отладочным ключом) и выкладывает его артефактом.

1. Создайте репозиторий на GitHub и отправьте код (`.gitignore` уже исключает
   базу, PDF, `.env` и сборочные каталоги):

   ```bash
   git init
   git add .
   git commit -m "Учусь: веб + API + Android"
   git branch -M main
   git remote add origin https://github.com/<вы>/<репозиторий>.git
   git push -u origin main
   ```

2. Откройте **Actions → Android APK → Run workflow**. При необходимости укажите
   `server_url` (по умолчанию `https://virusadk.alwaysdata.net`).
3. Скачайте артефакт **uchus-debug-apk** и установите `uchus-debug.apk` на телефон
   (разрешите установку из неизвестных источников).

Сборка локально (нужны JDK 17 и Android SDK 35):

```bash
cd android
gradle assembleDebug -PserverUrl=https://<логин>.alwaysdata.net
# android/app/build/outputs/apk/debug/app-debug.apk
```

> В архив не входит `gradle-wrapper.jar`. Если открываете проект в Android Studio,
> один раз выполните `gradle wrapper` в каталоге `android/` — студия сама
> предложит это сделать. В GitHub Actions Gradle ставится автоматически.

Для совместимости обновлений локальная сборка и CI используют общий
debug-ключ [android/keystore/uchus-debug.keystore](android/keystore/uchus-debug.keystore).
Не заменяйте его без необходимости: APK с другой подписью Android не установит
поверх уже установленного приложения. Это отладочный ключ, а не ключ Google Play.
Если раньше было установлено приложение, подписанное другим ключом, один раз
удалите его и установите APK с сайта заново — дальше обновления будут
устанавливаться поверх.

Для публикации в Google Play нужен release-ключ и `signingConfig` — debug-APK
подходит для установки вручную и тестирования.

### Публикация APK на сайте и автообновление

На главной странице сайта есть кнопка **«Скачать APK»**. Она ведёт на постоянный
адрес `/download/android`, а приложение при каждом запуске проверяет
`GET /api/v1/app/version` и предлагает обновление, если на сервере версия новее.

Файлы релиза лежат на сервере в `data/releases/` (в Git не попадают):

```text
data/releases/uchus-debug.apk
data/releases/version.json
```

`version.json`:

```json
{
  "version_code": 4,
  "version_name": "1.3",
  "file_name": "uchus-debug.apk",
  "size": 19648212,
  "sha256": "8cb34aa230832dacaa2c20f635ff59b888ad37506a72573f525e414b13298297",
  "notes": "Что нового",
  "published_at": "2026-10-26T12:00:00+00:00"
}
```

Чтобы выпустить обновление:

1. Увеличьте `versionCode` и `versionName` в
   [android/app/build.gradle.kts](android/app/build.gradle.kts).
2. Соберите APK и замените `data/releases/uchus-debug.apk`.
3. Увеличьте `version_code`, обновите `version_name`, `sha256` и `size` в
   `version.json`.
4. Загрузите оба файла на сервер в `~/edu-math/data/releases/`.

Старые установленные приложения увидят новый `version_code` и покажут диалог
«Доступно обновление» с кнопкой «Скачать».

## 🔌 JSON API

Полное описание — [docs/API.md](docs/API.md). Кратко:

```http
POST /api/v1/auth/login          {"login": "…", "password": "…"} → {"token": "…"}
POST /api/v1/auth/google         {"id_token": "…", "nonce": "…"} → сессия или needs_signup
POST /api/v1/auth/google/finish  {"signup_token": "…", "role": "student", …} → сессия
GET  /api/v1/map                 Authorization: Bearer <token>
GET  /api/v1/learners            X-Device-Id: <uuid>   # семейные профили
```

* Токены — непрозрачные, хранятся в БД в виде SHA-256-хэша, отзываются при выходе,
  живут 180 дней.
* CSRF для `/api/v1/*` не применяется (токен в заголовке), cookie-сессии не нужны.
* Ошибки единообразны: `{"ok": false, "error": "…", "message": "…"}`.
* Права те же, что на сайте: учитель видит только свои классы
  (`school_classes.teacher_id`), родитель — только привязанных детей.
* Правильные ответы тестов и работ не уходят клиенту до сдачи.

## 🔒 Безопасность и приватность

Данные детей — чувствительная информация, поэтому доступ ограничен явно:

* **Изоляция семей.** Профили, созданные в вебе, привязаны к случайному ключу
  семьи в подписанной cookie-сессии. Главная страница и `/family` показывают
  только профили своей семьи; чужие профили недоступны и по прямой ссылке (404).
  В мобильном API та же роль у заголовка `X-Device-Id`.
* **PIN профиля.** Если у профиля задан PIN, вход в него в вебе требует код;
  попытки ограничены на сервере (`services/rate_limit.py`), а не в cookie.
* **Родительская зона.** Показывает только профили своей семьи (или детей
  родительского аккаунта). PIN генерируется через `secrets`, попытки
  блокируются на сервере. Профили, созданные до обновления, можно добавить в
  свою семью вручную — остальные останутся скрытыми.
* **Регистрация учителя** не позволяет занять класс, который уже ведёт другой
  учитель, и принимает только классы выбранной школы. Админка может назначить
  учителя принудительно.
* **Загрузки** проверяются по сигнатуре файла, а не только по расширению
  (`services/filecheck.py`): PDF и фото должны действительно быть PDF/JPEG/PNG.
* **HTTPS.** Android-клиент по умолчанию запрещает cleartext-трафик, HTTP
  разрешён только для `localhost`/эмулятора. Для продакшена задайте
  `SECRET_KEY` и `COOKIE_SECURE=1`.
* **Google OAuth.** `state` одноразовый и сравнивается за постоянное время;
  почта принимается только с `email_verified=true`; `sub` Google уникален
  (частичный уникальный индекс в БД); привязка по почте — только при
  однозначном совпадении; токены Google не сохраняются.
* **Секреты.** Если `SECRET_KEY` пуст, приложение создаёт постоянный ключ в
  `data/.secret_key` (файл в `.gitignore`) вместо падения на первом запросе.
